Auth and leaderboard · Component

LeaderboardService

Posting a score and loading the week's tables, independent of where they go. On the iPhone it's Apple Game Center: a leaderboard that restarts each week (2026-10-23). Android has none yet, so no Post score.

Used when
Post score at the end of a session or from History; the Leaderboards tab and View leaderboard (iPhone)

Like AuthService, the UI and the game see only the interface (signIn, submit, show), so tests use a fake, and the app's own leaderboard on Amplify and the website (ranking iPhone and Android together, backlog #21) can replace or join Game Center later without touching Play.

main overrides leaderboardServiceProvider with GameCenterLeaderboardService only on the iPhone. It uses the games_services plugin (5.3.0); the plugin's Google Play Games start-up pieces are removed from the Android manifest, so Android starts as before.

A score is posted once, only when the player taps Post score: the total, shown under their Game Center nickname. Once posted, the game's scores are locked, so the leaderboard always matches Play.

The tables (2026-10-23, backlog #22): loadTable uses the app's own iPhone code, GameCenterTables in AppDelegate.swift, on the channel thrower/game_center. The plugin can't load last week's full table, and it loads every player's photo, which isn't shown. Names and scores only, plus the week's start. To compile on the Mac.
