AuthService

The app's sign-in, behind an interface. Since stage 2 of the Accounts Roadmap (2026-10-19) it's AWS Amplify: Cognito, email sign-in, in London (eu-west-2). Signing in is never needed to score.

At start, main reads the deployed backend's settings from the asset assets/config/amplify_outputs.json (loadAmplifyOutputs; gitignored, one per branch). With them, connectAccounts adds the Cognito plugin, configures Amplify and returns an AmplifyAuthService, which overrides authServiceProvider. Without them, or if Amplify can't be configured, the provider is null and the app runs signed out, as it always has.

AmplifyAuthService follows the Hub's sign-in events (signed in, signed out, session expired, user deleted). The user's ID is the Cognito sub, never the email; the display name is the email.

The backend lives in the repo (amplify/, Amplify Gen 2: defineAuth with email sign-in; Google and Sign in with Apple come in Task 3). Amplify Hosting deploys it from GitHub (amplify.yml: ampx pipeline-deploy): main is production, dev development. Its only web page is web_public/, later home to the privacy policy.

Nothing leaves the phone unless the build has the settings and the user signs in (their email and password, to Cognito). No Account screen yet (Task 2).
